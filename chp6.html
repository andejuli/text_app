Chapter 6

SQL Querying Tools

Learn how SQL functions, joins, and summary queries help turn stored data into clear, useful information for analysis and decision-making.

Beyond Single-Table Queries

In the last chapter, we focused on the core syntax of single-table queries. Those basics remain important, but SQL becomes far more useful when we can reshape values, combine related tables, and summarize large sets of rows. For information systems work, these tools are essential because they help turn raw database content into information that people can actually use.

Functions That Shape Data

SQL functions let you work with values before they are displayed or stored. Scalar functions operate on one row at a time, which makes them useful for cleaning text, adjusting numbers, and extracting parts of dates. This is especially helpful when data needs to be standardized for reports or analysis.

Text Functions

Text functions combine or transform strings. They can build readable labels, change letter case, or pull part of a word from a column value.

SELECT CONCAT('The primary key of ', prod_name, ' is ', product_id) AS new_string
FROM products
WHERE product_id = 1;

Result

new_string
The primary key of cocoa mug is 1
 
SELECT LEFT(category_name, 4) AS left_part,
       LENGTH(category_name) AS char_count,
       UPPER(category_name) AS upper_category
FROM categories
WHERE category_id = 2;

Result

left_partchar_countupper_category
Offi6OFFICE

Numeric and Date Functions

Numeric functions are useful when values need to be rounded, compared, or formatted for display. Date and time functions help pull out parts of a date, calculate time differences, or present dates in a friendlier format.

SELECT ROUND(prod_price) AS rounded_price,
       FLOOR(prod_price) AS lower_whole,
       CEILING(prod_price) AS upper_whole
FROM products
ORDER BY product_id;

The product, supplier, and category tables do not contain dates, so this example uses the hire_date column from an employee table. EXTRACT retrieves the year and month from each date.

SELECT hire_date,
       EXTRACT(YEAR FROM hire_date) AS hire_year,
       EXTRACT(MONTH FROM hire_date) AS hire_month
FROM employee
ORDER BY hire_date;

SQL also provides operations for working with current dates and times, adding or subtracting time intervals, and formatting dates. The syntax for these operations can vary between database systems, so check the documentation for the system you are using.

Joining Related Tables

Relational databases are split into related tables during normalization, so the information often has to be joined back together for reporting. A JOIN combines rows from tables that share a related key. In most cases, that means matching a primary key in one table to a foreign key in another. Using explicit join syntax keeps the relationship clear and readable.

INNER JOIN is the most common join. It returns only rows that have matching values in both tables.

SELECT prod_name, supplier_name
FROM products
INNER JOIN suppliers
    ON products.supplier_id = suppliers.supplier_id
ORDER BY prod_name;

Result

prod_namesupplier_name
book bagBag Emporium
cocoa mugGeneral Supply
desk lampOffice Supply Co

When a query needs data from three related tables, it can use a series of JOIN clauses. The example finds products in the Office category and displays each product’s category and supplier.

SELECT prod_name, category_name, supplier_name
FROM products
    JOIN categories
        ON products.prod_category = categories.category_id
    JOIN suppliers
        ON products.supplier_id = suppliers.supplier_id
WHERE category_name = 'Office'
ORDER BY prod_name;

Result

prod_namecategory_namesupplier_name
desk lampOfficeOffice Supply Co
notebookOfficeOffice Supply Co

An OUTER JOIN matters when completeness is more important than matching rows alone. A LEFT JOIN keeps every row from the left table even when there is no match on the right, which is useful when missing related data should still be visible.

Summary Queries

When a business question asks for a total, an average, a highest value, or a count, SQL uses aggregate functions. These functions operate on a set of rows and return a single result, which makes them ideal for dashboards, reports, and decision support.

SELECT AVG(prod_price) AS average_price
FROM products;

Result

average_price
11.568333
 
SELECT COUNT(*) AS number_of_products
FROM products;

Result

number_of_products
6

The GROUP BY clause organizes rows that share the same value into groups. An aggregate function can then summarize each group. In this example, products are grouped by supplier, and COUNT(*) counts the products in each group.

SELECT supplier_id, COUNT(*) AS Number_of_Products
FROM products
GROUP BY supplier_id
ORDER BY supplier_id;

Result

supplier_idNumber_of_Products
12
22
31
41

The HAVING clause filters groups after the data has been summarized with GROUP BY. Unlike WHERE, which filters individual rows before grouping, HAVING filters the completed groups. This example keeps suppliers with more than one product.

SELECT supplier_id, COUNT(*) AS Number_of_Products
FROM products
GROUP BY supplier_id
HAVING COUNT(*) > 1
ORDER BY supplier_id;

Result

supplier_idNumber_of_Products
12
22

Views

A view is a saved query that acts like a virtual table. Views can simplify repeated queries, hide unnecessary columns, and provide a consistent way to access information.


CREATE VIEW expensive_products AS
SELECT prod_name, prod_price
FROM products
WHERE prod_price > 10;

The CREATE VIEW statement saves the query. To display its rows, run:


SELECT prod_name, prod_price
FROM expensive_products
ORDER BY prod_price DESC;

Result

prod_nameprod_price

Why This Matters

Functions, joins, and summary queries are some of the most practical tools in SQL. Functions clean and format values, joins reconnect related tables, and aggregates convert rows of data into information that is easier to interpret. For information systems students, these are the skills that make database data useful in real applications.

Using AI to Draft SQL Queries

AI tools can help draft SQL queries from a question written in plain language. To get a useful query, identify the database system, provide the relevant table and column names, and describe the results you want.

For example, a prompt might say: “Using PostgreSQL, write a query that lists product names, category names, and supplier names for products in the Office category. Use the products, categories, and suppliers tables. Explain how the tables are joined.”

AI-generated SQL can contain incorrect table or column names, use syntax for a different database system, or answer the question incorrectly. Compare the query with the database structure, run it on sample data, and check that the results make sense before relying on them. The analyst remains responsible for understanding and verifying the query.
